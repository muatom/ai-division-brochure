# EDITING · איך עורכים את הגיליון

> לקלוד ולתום. **קובץ ה-HTML הוא המקור היחיד.** אין קובצי מקור נפרדים ואין שלב בנייה: עורכים, שומרים, מרעננים את הדפדפן.
> גרסה 3 (07/10/2026): הפריסה נקבעת לפי התעדוף של כל פעילות, ולכל פעילות יש קטגוריה עסקית.

## 1 · מפת הקובץ

הקובץ בנוי מבלוקים. כל בלוק פותח בכותרת עם מספר בסוגריים מרובעים, וכך מוצאים אותו בחיפוש.

| ‏[B] נכסים | ‏`[B] נכסים` | ארבעת הפונטים והלוגו, מקודדים ב-base64. שורות ארוכות מאוד | **לא ביד.** ראו סעיף 8 |
| ‏[C] המדיה | ‏`[C] המדיה` | התמונות (ובעתיד הסרטונים) של עמודי הזרקור, מקודדים, כל אחד עם שם. מבלוק התוכן מפנים אליהם בסולמית | **לא ביד.** ראו סעיף 3 |
| ‏[1] התוכן | ‏`[1] התוכן` | כל הטקסט והפעילויות | **כן. כאן עושים כמעט הכול** |

## 2 · מבנה התוכן (`window.CONTENT`)

| שדה | מה הוא קובע |
|------|--------------|
| ‏`meta` | שם הגיליון, מספר, חודש, שם התחום, ו-`placeholders` (תגית "מקום לתמונה או לסרטון", ראו סעיף 3) |
| ‏`cover` · `editorial` · `howto` | השער, דבר העורך, וארבע השורות של "איך קוראים את הגיליון" |
| ‏`numbers` | הטקסטים של עמוד המספרים ושל עמוד התחומים |
| ‏`catsPage` | הטקסטים של עמוד הפתיחה של הקטגוריות (כותרת ופתיח). שאר העמודים נבנים מ-`cats` |
| ‏`cats` | הקטגוריות העסקיות: `viz` ‏`agent` ‏`auto` ‏`system` ‏`ml`, ועוד `method` שאינה קטגוריה (`extra`). לכל אחת `name` ‏`en` ‏`short` ‏`long` ‏`icon` ‏`glyph` |
| ‏`ladder` | עמודי הסולם, כולל `base`: פס ה-L0 |
| ‏`levels` · `gateLabels` | ארבע הרמות והתוויות בשער הרמה |
| ‏`statuses` | שלושת הסטטוסים: `'פעיל'` ‏`'בפיילוט'` ‏`'בדרך'`, והנוסח שלהם בכרטיס |
| ‏`tiers` | השמות של שלוש דרכי ההצגה: בזרקור, בפוקוס, בקצרה |
| ‏`areas` · `crossArea` | שבעת התחומים העסקיים והצוותים שלהם, והשם של פעילות רוחבית (`'כלל הארגון'`) |
| ‏`items` | כל הפעילויות, לפי רמה. לכל רמה: `split` (כמה שורות בכל עמוד "בקצרה") ו-`list` |
| ‏`teaser` | הטיזר לגיליון הבא: התיבה בתוכן העניינים והעמוד לפני הגב |
| ‏`closing` · `glossary` | הגב והמילון |
| ‏`allowedPMs` | שמות מנהלי המוצר שמותר להציג. בדיקת האיכות מתריעה על כל שם אחר |

**פעילות (שורה ב-`items[n].list`):**

| שדה | מה הוא | חובה? |
|------|--------|-------|
| ‏`pri` | התעדוף מהאקסל: `1` בזרקור · `2` בפוקוס · `3` בקצרה | כן |
| ‏`title` | השם המלא (לחיפוש, לכרטיס ולשורה) | כן |
| ‏`area` | התחום העסקי: אחד מהשמות ב-`areas`, או `'כלל הארגון'` | כן |
| ‏`unit` | עבור מי | כן |
| ‏`cat` | הקטגוריה: `viz` ‏`agent` ‏`auto` ‏`system` ‏`ml` ‏`method` | כן |
| ‏`status` | ‏`'פעיל'` ‏`'בפיילוט'` ‏`'בדרך'`. בכל מה שאינו פעיל התווית "הערך" מתחלפת לבד ל"הערך הצפוי" | כן |
| ‏`what` · `value` | מה זה עושה, ומה הערך (`value` אפשר ריק) | ‏`what` כן |
| ‏`pm` | מנהל/ת מוצר, רק מתוך `allowedPMs` (אפשר ריק) | לא |
| ‏`name` · `h1` | בזרקור ובפוקוס: השם הקצר מעל הכותרת, והכותרת עצמה. **הכותרת אומרת מה הפעילות עושה, במילים פשוטות.** `*כוכביות*` = החלק הכחול | בזרקור ובפוקוס |
| ‏`pull` | הערך כשורה בולטת: `{from, to, note}` לפני ואחרי · `{big, note}` משפט · `{stat, count, statNote, also}` מספר גדול (`count` = המספר שסופר מאפס). בלי `pull` מוצג `value` | לא |
| ‏`art` | שם האיור (סעיף 4) | בזרקור ובפוקוס |
| ‏`line` · `takeaway` | בזרקור: משפט "איך זה עובד" (בלי `line` מוצג `what`), ופס כהה אופציונלי | לא |
| ‏`media` | בזרקור: תמונה או סרטון, סעיף 3 | לא |

**"להרחבה" והסיפור המלא.** לכל פעילות יש כפתור "להרחבה" שפותח את הכרטיס שלה. מוסיפים לפעילות שדה `more`, והכרטיס מקבל פרק "הסיפור המלא":
   ```
   more: { lead: 'פסקה אחת: הבעיה העסקית והמוצר',
           steps: ['שלב ראשון', 'שלב שני', 'שלב שלישי'],
           facts: [['המוצרים', '...'], ['עבור', '...']] },
   ```
   כל החלקים לא חובה. רק עובדות מהבריף או ממקור שתום אישר.

**הסדר בתוך רמה** קובע את הסדר בגיליון: קודם כל בזרקור, אחר כך בפוקוס (בזוגות, לפי הסדר ברשימה), ובסוף בקצרה.

**הזרקור הראשון בכל רמה מקבל כפולה:** הטקסט בעמוד הימני, והתמונה או האיור על עמוד שלם משמאל. רוצים שפעילות אחרת תקבל את הכפולה? מעבירים אותה לראש הרשימה של הרמה. כרגע: סוכן להכנת מצגות (L1), זירת התביעות האמבולטוריות (L2), ביצועי קמפיינים במערך הסיכונים (L3), MATCH-UP (L4).

## 3 · תמונות וסרטונים בעמודי הזרקור

לכל פעילות בתעדוף 1 יש עמוד מלא עם תיבת מדיה (16:9). בארבע הכפולות (הזרקור הראשון בכל רמה) התמונה מקבלת עמוד שלם, ביחס 16:10. עד שמגיעה תמונה או סרטון, מוצג בתיבה האיור, ועליו תגית "מקום לתמונה או לסרטון".

**הדרך המומלצת: בלוק המדיה `[C]`.** התמונה מקודדת פעם אחת לבלוק בסוף הקובץ ומקבלת שם, ובבלוק התוכן מפנים אליה בסולמית:
   ```
   media: { type: 'image', src: '#arena-1', alt: 'מסך הזירה' },
   ```
   ככה בלוק התוכן נשאר קריא. את הבלוק מעדכנים עם Claude (או ביד: שורה חדשה בצורה `'arena-1': 'data:image/webp;base64,....',`). התמונות המקוריות, אחרי חיתוך וכיווץ, נשמרות ב-`assets/media/`.

**צילומי מסך מטלפון:** `type: 'phones'` מציג עד שלושה טלפונים שעולים מתחתית התיבה, והאמצעי גדול וגבוה יותר. הסדר ב-`src` הוא מימין לשמאל:
   ```
   media: { type: 'phones', src: ['#migdalor-listen', '#migdalor-home', '#migdalor-story'], alt: ['...', '...', '...'] },
   ```
   לפני ההטמעה חותכים את שורת הסטטוס (שעה, סוללה) מראש הצילום, ומכווצים לרוחב 440 פיקסלים ב-WebP. כל טלפון שוקל כך 20 עד 40KB.

**צילום מסך של כלי בדפדפן:** `type: 'screen'` מציג את הצילום בתוך חלון דפדפן, עם שם בשורת הכתובת:
   ```
   media: { type: 'screen', src: '#elementar-dashboard', url: 'דשבורד הנהלה בכירה · אלמנטר', alt: '...' },
   ```

**זרימה מצוירת של MATCH-UP:** `type: 'match'`. כל המילים (המקורות, המנוע, מפתחות ההצלבה, המאשר, הקופה) בשדות של `media` בפעילות, ומשנים אותן שם.

**צילום של חלון צד בתוך CRM:** אותו `type: 'screen'` עם `host: 'crm'`. הצילום מוצג כחלון בצד שמאל, ושאר המסך מצויר כשלד בלי נתונים. `ask` הוא הטקסט בשורת הכתיבה. **לפני שמכניסים צילום מ-CRM, חותכים ממנו כל פרט של לקוח.**

**קליפ קצר במקום צילום:** ליד `src` מוסיפים `clip: '#clip-migdalor'` ו-`poster: '#poster-migdalor'` (הפריים המוגמר, שמוצג בהדפסה ובהפחתת תנועה). הקליפ בלי קול, בלולאה, מתנגן רק כשהעמוד מוצג ומתחיל מהתמונה המוגמרת. שלושת הקליפים הקיימים: `clip-migdalor`, `clip-elementar`, `clip-kms`. להוספת קליפ משלכם: mp4 בקידוד H.264 וללא קול (עד כ-0.3MB), מקודד ל-base64 בפקודה שבסעיף 8, ונכנס לבלוק [C] בצורה `'clip-שם': 'data:video/mp4;base64,...'`.

**מצגת מצוירת (בלי קובץ):** `type: 'deck'` מצייר חלון PowerPoint עם שקף בשפת המותג. משנים בו רק מילים. עם `chat` מופיע לידו חלון שיחה עם הסוכן (`u` העובד, `a` הסוכן, ואפשר קובץ מצורף כפריט שלישי):
   ```
   media: { type: 'deck', file: 'ועדת היגוי.pptx', kicker: 'תחום Data & AI', title: 'ועדת היגוי', sub: 'תמונת מצב',
            chat: [['u', 'צריך מצגת לוועדת ההיגוי, מתוך הבריף', 'בריף הפרויקט.docx'], ['a', 'מה ההחלטה שאתם מבקשים?'], ['a', 'המצגת מוכנה']] },
   ```

**עוד שתי דרכים להכניס קובץ:**
1. **הכי פשוט, ועדיין קובץ אחד:** תמונה (PNG או JPG, רצוי עד 1MB) מקודדת לתוך הקובץ. בשדה `media` של הפעילות:
   ```
   media: { type: 'image', src: 'data:image/png;base64,....', alt: 'מסך הסימולטור', fit: 'cover' },
   ```
   הקידוד: פקודת ה-PowerShell שבסעיף 8.
2. **סרטון, או תמונה גדולה:** הקובץ יושב בתיקייה `media/` ליד ה-HTML, והשדה מפנה אליו:
   ```
   media: { type: 'video', src: 'media/arena.mp4', poster: 'media/arena.jpg', alt: 'הדגמה של הכלי' },
   ```
   **אז מעבירים את התיקייה `media/` יחד עם הקובץ.** בלעדיה התיבה תהיה ריקה.

- `fit: 'contain'` מציג את כל התמונה בלי חיתוך (לצילום מסך). ברירת המחדל, `cover`, ממלאת את התיבה וחותכת שוליים.
- סרטון מתנגן בלי קול, בלולאה, ורק כשהעמוד או השקף מוצגים. מי שהגדיר "הפחתת תנועה" מקבל אותו עם כפתורי הפעלה.
- **להסתיר את כל תגיות ה-placeholder בבת אחת:** `meta.placeholders: false`. האיורים נשארים.

**ארבעת העמודים שעוד מחכים לתמונה או לסרטון:** זירת התביעות האמבולטוריות · דשבורד תקלות · ביצועי קמפיינים, מערך הסיכונים · בקרת תמחור רכב. ב-MATCH-UP יש זרימה מצוירת. כבר יש: שלושה צילומי מסך ב"המגדלור AI", צילום של דשבורד הנהלה אלמנטר, ומצגת מצוירת בסוכן המצגות. בדיקת האיכות (`?qa`) סופרת כמה מהם עדיין בלי מדיה.

## 4 · האיורים (בלוק [2ב])

| סוג | גודל | איפה | איך בוחרים |
|------|------|------|-------------|
| ‏A · רחב | ‏520x270 | בתיבת המדיה של עמוד בזרקור, ועל העמוד השמאלי של הכפולה | ‏`art` של הפעילות |
| ‏B · לאורך | ‏240x300 | בפס התמונות של עמוד בפוקוס (דיפטיך), ובטלפון מעל כל טור. הזרימה מלמעלה למטה | ‏`art` של הפעילות. אין איור לאורך באותו שם? מוצג הרחב |
| ‏G · סמל | ‏64x64 | בעמודי הקטגוריות ובשקף הקטגוריות | ‏`glyph` של הקטגוריה |

- **פעילות שעולה לבזרקור** צריכה איור רחב, ו**פעילות שיורדת לבפוקוס** צריכה איור לאורך. לחלק מהפעילויות כבר יש שני האיורים, באותו שם (למשל `chat`, `query`, `donut`). הרשימות המלאות: `ART.kinds` (רחבים) ו-`ART.minis` (לאורך), בקונסול של הדפדפן.
- איור חדש = פונקציה חדשה ב-`A` או ב-`B`, עם העוזרים שבראש הבלוק (`card`, `chip`, `lines`, `arrow`, `frame`...). הצבעים רק דרך המחלקות (`acc`, `soft`, `ink`...), וכך אותו איור עובד בכל ארבע הרמות.
- בלי מספר או נתון שלא בבריף, ולכל היותר ארבע תוויות קצרות.

## 5 · אסימונים והדגשות

- `{total}` כל הפעילויות · `{active}` פעיל · `{pilot}` בפיילוט · `{soon}` בדרך · `{areas}` התחומים · `{cats}` הקטגוריות · `{L1}`..`{L4}` לפי רמה. **מחושבים מהרשימות.**
- `*טקסט*` בכותרות: הדגשה בכחול (ב-L2 בירוק). בפסים הכהים: הדגשה במנטה. ב-`pull.big`: הדגשה בירוק.
- `\n` שבירת שורה. מספר לעולם לא נשבר מהמילה שאחריו, הקוד מדביק אותם לבד.

## 6 · מתכונים

**לשנות טקסט של פעילות.** מחפשים את השם שלה בבלוק [1] ומשנים את השדה. הניוזלטר, המצגת, החיפוש והכרטיס מתעדכנים יחד.

**להוסיף פעילות.** מוסיפים שורה ב-`list` של הרמה, במקום שמתאים לתעדוף שלה. בתעדוף 3 מעדכנים גם את `split` של הרמה (עד חמש שורות בעמוד, ובשורות ארוכות ארבע). בתעדוף 2 מספר הפעילויות ברמה חייב להיות זוגי. **מספר העמודים הכולל חייב להיות זוגי**, אחרת הגב לא נופל לבד בצד ימין. בדיקת האיכות מתריעה על כל אחד מהשלושה.

**כפולה מתחילה תמיד בעמוד זוגי.** הסולם, שער כל רמה והזרקור הראשון בכל רמה תופסים כפולה כל אחד. עמוד שנוסף או ירד לפניהם מזיז אותם לצד הלא נכון, ואז שני החצאים נופלים על שני גיליונות. בדיקת האיכות כותבת איזו כפולה זזה. הפתרון: לשנות את `split` של אחת הרמות שלפניה כך שתוסיף או תוריד עמוד אחד. למשל ברמה 2 `split: [4]` במקום `[2, 2]` מוריד עמוד, ו-`[2, 2]` במקום `[4]` מוסיף.

**לשנות תעדוף.** משנים את `pri`, ומזיזים את השורה למקום שמתאים לה ברשימה. בדיקה: לפעילות בזרקור יש `art` רחב, לפעילות בפוקוס יש `art` לאורך, ולשתיהן `name` ו-`h1`.

**להעביר פעילות בין רמות.** גוזרים את השורה מרמה אחת לאחרת, ומעדכנים את `split` בשתיהן.

**לשנות סטטוס או קטגוריה.** משנים `status` או `cat`. המספרים, פס הסטטוס, האינדקס והדוגמאות בעמודי הקטגוריות, והחלוקה לקטגוריות בשער של כל רמה, מתעדכנים לבד.

**לאשר מנהל/ת מוצר.** מוסיפים את השם ל-`allowedPMs` ולשדה `pm` של הפעילויות. השמות שממתינים, ב-`DECISIONS.md`.

**להוסיף מונח למילון.** שורה ב-`glossary`. מונח באנגלית מקבל קו מנוקד והגדרה במעבר עכבר, ומופיע תחת "מונחים בכרטיס" בכל פעילות שמזכירה אותו. מונח בעברית מקבל הגדרה במעבר עכבר רק אם הוא ברשימה הקצרה בבלוק [3] (חפשו `'אכ״ע', 'חא״ט'`), כי מילה עברית מופיעה בהרבה צורות.

**גיליון חדש** (למשל הגיליון של הסוכנים החכמים). מעתיקים את הקובץ לשם חדש (`AI-בחטיבה-גיליון-02.html`) ומעדכנים את `meta`, התוכן והטיזר. הגיליון הקודם נשאר כמו שהוא, כי הוא כבר נשלח.

## 7 · בדיקה לפני ששולחים

מוסיפים לכתובת בדפדפן:

| תוספת | מה היא עושה |
|--------|--------------|
| ‏`?qa` | תיבת בדיקה: גלישת טקסט, ספירות, `split`, זוגיות של בפוקוס ושל העמודים, כפולה שמתחילה בעמוד אי-זוגי, קטגוריה, סטטוס ותחום תקינים, איור לכל פעילות בזרקור ובפוקוס, סמל לכל קטגוריה, שמות מאושרים, קו מפריד ארוך, פונט, וכמה עמודי זרקור עדיין בלי מדיה |
| ‏`?still` | בלי אנימציות. טוב לצילומי מסך |
| ‏`?view=spread` · `single` · `reader` | כופה פריסה: כפולה, עמוד בודד, גלילה |
| ‏`#p12` · `#s5` | קופץ לעמוד 12 או לשקף 5 |

**רשימת בדיקה:** 1. ‏`?qa` מראה "לא נמצאו בעיות", גם בניוזלטר וגם במצגת. 2. דפדוף מהשער לגב. 3. מצב מצגת מההתחלה עד הסוף. 4. פתיחה בטלפון או בחלון צר. 5. הדפסה ל-PDF מחלון "תוכן". 6. אין שם שלא ב-`allowedPMs`, ואין מספר שלא בבריף.

**אם הבדיקה מדווחת על גלישת טקסט:** מקצרים את הטקסט, או מפצלים את העמוד דרך `split`. לא מקטינים פונט כדי לדחוס.

## 8 · החלפת פונט או לוגו, וקידוד תמונה

הנכסים המקוריים יושבים ב-`assets/`. בקובץ הם מופיעים כ-base64 בבלוק [B], בשורה אחת לכל קובץ.
כדי להחליף: מקודדים את הקובץ החדש ומחליפים את המחרוזת שאחרי `base64,` באותה שורה. אותה פקודה מקודדת גם תמונה לתיבת מדיה (סעיף 3).

- **ב-Windows (PowerShell 5.1):**
  ```
  [Convert]::ToBase64String([IO.File]::ReadAllBytes('C:\path\to\file.png')) | Set-Clipboard
  ```
  ואז מדביקים במקום המחרוזת.

הלוגו הוא מסכה: לבן על שקוף. הצבע שלו נקבע ב-CSS (נייבי על רקע בהיר, לבן על כהה), ולכן אותו קובץ משמש לשני המצבים. לוגו חדש צריך להיות לבן על רקע **שקוף לגמרי**.
